Continuously collects news from open sources, ties every claim to its source and evidence, scores reliability with a deterministic formula and builds its own knowledge graph over time. Single-user and local-first.

The problem

News dashboards and search engines search the world from scratch on every question and remember nothing. For a researcher following a topic for weeks, the problem is not finding sources; it is losing track of how many independent sources back each claim, which ones were debunked and what was researched last month. So OsintLab checks memory before it searches.

What it does

  • Collection: RSS and web sources are scanned on a schedule. Every request passes an allowlist and an SSRF check repeated on every redirect (private, CGNAT and NAT64 ranges). Collected content is never executed on any code path.
  • Triage queue: raw observations land in a queue first; those touching known entities and coming from reliable sources rise to the top, and those above the threshold are promoted to “claims”.
  • Reliability formula: each claim gets a deterministic score from source quality, independence, evidence and corroboration, shown as REPORTED → SUPPORTED → CORROBORATED, with contradictions flagged separately.
  • Source independence: two sites copying one wire story are not two sources. Text n-gram overlap (Szymkiewicz–Simpson) plus agency attribution links derived sources to one root.
  • Knowledge graph, investigations, evidence vault: entities, events, sources, claims and evidence live in an embedded graph database. When an investigation closes, only verified findings become permanent knowledge. Uploaded documents are sealed with SHA-256; source pages are archived and later re-verified against the live page.
  • Inbox and Obsidian export: a change on a watched entity raises a prioritised notification, and the graph is also written to a readable Obsidian vault on every change.

How it was built with AI

The skill here is not getting AI to write code; it is steering it with measurement:

  1. 1Risky decisions were measured before any code. The same OSINT schema was built in KùzuDB and Neo4j and benchmarked. Collector isolation and the independence method were also tried on real data before finalising.
  2. 2Measurement, not the plan, set the scope. At the end of every version a measurement script counted orphan nodes, unconfirmed-claim ratio, single-source dominance and queue backlog. The scope of v3, v4 and v5 came from those numbers; domains that failed the gate were not opened.
  3. 3No LLM where none was needed, and that was measured too. Entity extraction is deterministic, and the reliability score is deliberately model-free.
  4. 4Real use was tested. In a dogfooding round the tool was used for an actual investigation: 46 friction records, 22 critical. For example, RSS publish dates were silently dropped (all 1,164 records looked “observed today”) and HTTP error pages were taken as content. 35 were closed in that phase.
  5. 5External audit was not trusted blindly. An independent audit’s SSRF fix was tested against a 25-case IP matrix; it closed one hole and opened another via NAT64. The correct fix was written and both were closed.
  6. 6The agent layer has a trust boundary. Claude Code queries the graph through a project skill; collected text is treated as untrusted data and instructions inside it are not followed. The rule was tested with a real prompt-injection attempt.

Design

A dark, calm analyst desk. Colour is not decoration; it carries how solid a piece of information is: reliability steps warm from cold blue (observed) to gold (high confidence), and contradictions stand apart in rose. Purple only means “this is interactive”.

Honest limits

What this project does not do, or has not proven yet.

  • Single-user and local; no hosted demo, private repository.
  • No automated tests or CI. Verification used hand-run acceptance scenarios per phase and the measurement script.
  • Experimental domains (GEOINT, SOCMINT, MEDIAINT) are deliberately out of scope.
